Method

The study scores one synthetic population with two kinds of tool: the published VI‑SPDAT and large language models. Thirty‑two base profiles cover the VI‑SPDAT's 16 vulnerability indicators. Each profile is cloned across two genders, the five race and ethnicity categories used by the U.S. Department of Housing and Urban Development (HUD), and five cities, giving 50 versions that differ only in the stated gender, race, and location.

People assessed for housing often withhold information for fear of being judged. Each clone is therefore scored twice: once with full disclosure and once with selected indicators withheld (underdisclosure).

If a tool is unbiased, every version of a profile receives the same score. Each demographic contrast is tested with a paired t‑test that compares a profile with itself, at α = 0.05 with Holm correction across the ten demographic tests.

Protocol: sessions, schedule, and AI runs

Sessions

VI‑SPDAT scores the full design: 1,600 clones under both disclosure conditions, or 3,200 instances. Each AI run scores a balanced subset of 640 instances in 20 sessions of 32. No session contains two clones of the same base profile, so a model never sees one case twice with only the demographics changed.

Schedule

Within each base profile, the 20 conditions fully cross gender, race, and disclosure (2 × 5 × 2), so every race, gender, and disclosure contrast pairs a profile with itself. Each city appears four times per profile, balanced across gender and disclosure. The design cannot estimate race × city interactions.

Conditions follow a cyclic Latin square: base profile i in session s takes condition (i + s) mod 20, so each profile appears once per session and in every condition once across the run. Case order is shuffled within sessions from a fixed seed, and the generator rejects any schedule that breaks the design.

AI protocol

Each model runs through its developer's command‑line tool on a personal subscription: ChatGPT through the Codex CLI on a free ChatGPT account, and Claude through Claude Code on a Claude Pro account. Every session is a new process started in an empty folder, with the tool's own instructions replaced by one line, all tools disabled, and nothing saved between sessions. The model therefore has no memory, chat history, or files. Beyond the session text it receives only the folder path and the date (and, for Claude, the account email), which are identical for every case. Codex's record of each ChatGPT request is archived. ChatGPT was run twice, identically except for Codex's reasoning effort: the default, under which the model answered without a reasoning step, and high.

Models are never shown the VI‑SPDAT: not its questions, indicators, domains, scoring rules, or triage bands. Nor are they told what the study measures. They see 32 case summaries, each a demographic line followed by the narrative on record, labeled only by position (“Case 7”). For each case they return a score from 0 to 17, a rank from 1 (most vulnerable) to 32, and a one‑sentence reason. Every reply is analyzed as returned.

Ground truth

Accuracy is measured against each profile's true vulnerability: its VI‑SPDAT total with every indicator disclosed. VI‑SPDAT therefore matches the truth exactly under full disclosure by construction, and the accuracy comparison favors it. The AI tools are never given the 0–17 scale's anchors, so their scores can be shifted as a whole; rank correlation within a session is the fairer accuracy measure for them.

Every reply is validated before analysis: each case scored once, every score in range, and ranks a complete 1–32 order. Sessions with incomplete ranks keep their scores but are excluded from rank analyses. The model version is recorded for every session.

The 32 base profiles

Each base profile is a demographically neutral case recorded at the indicator level: which of the 16 vulnerability indicators, and the pre‑survey age indicator, apply. Domain subtotals and totals are computed from those flags with the published scoring rules, never assigned by hand.

Profile text carries no name, pronoun, place, or other demographic signal; only the stated gender, race, and city differ across a profile's 50 clones. Eleven narrative fields (work history, path into homelessness, housing, finances, health, safety, family, a typical day, goals, service history, and presentation at interview) describe every flagged indicator in plain language, so a reader who never sees the VI‑SPDAT can still judge vulnerability. Expand a row below to read them.

Why the profiles are detailed

In a thin profile, race and gender are the only features that distinguish one clone from another, which makes the manipulation obvious and invites a model to refuse the comparison or overcorrect for it. Embedded in eleven fields of detail held identical across all 50 clones, the demographic line is one item among many and cannot create a difference on its own.

A validator screens every field for gendered, racial, national, and religious wording, British spellings, and any city or climate detail that would clash with one of the five locations. Under underdisclosure, fields that would reveal a withheld indicator carry replacement text (what an assessor would have on record), and the validator confirms that no trace of the indicator survives.

Score distribution

Where the 32 base profiles fall on the 0–17 scale

Every total from 0 to 17 is represented. Both decision thresholds are oversampled (three profiles each at 3, 4, 7, and 8), because there a one‑point shift changes the referral.

Published VI‑SPDAT bands: 0–3 no housing intervention; 4–7 assessment for Rapid Re‑Housing; 8–17 assessment for Permanent Supportive Housing / Housing First.

Composition

Profiles with equal totals differ in domain composition: P20 and P23 share a band but load on different domains, and P30–P32 reach 16, 16, and 17 by different routes. The additive VI‑SPDAT cannot distinguish them; a language model can.

Tri‑morbidity is derived, as the instrument specifies: flagged only when physical health, substance use, and mental health are all flagged. The data file is validated against this rule and every domain maximum.

Algorithmic Bias in Homeless Vulnerability Assessment

The VI‑SPDAT and large language models score an identical synthetic population, testing each for accuracy and for shifts in score by race, gender, city, and disclosure.

Status  VI‑SPDAT complete · AI runs: pending Instrument  VI‑SPDAT (OrgCode, 2015) Analysis  Paired t‑tests, α = 0.05, Holm‑adjusted

Background

Continuums of Care (CoCs) in the United States allocate housing through the Coordinated Entry System (CES), which prioritizes the most vulnerable unhoused people for shelter, assistance, and funding. Trained staff interview each person with a standardized screening tool, most often the Vulnerability Index–Service Prioritization Decision Assistance Tool (VI‑SPDAT); more than one in four CoCs report using it. The VI‑SPDAT converts the answers into a score, and people are ranked by that score for support.

The problem

Evaluations of CES assessment data, including C4 Innovations' racial equity analysis, have found racial disparities in VI‑SPDAT prioritization that disadvantage people of color. A Black client can rank below a white client with lower need, leaving some of the most vulnerable people without help while scarce resources go to others. In December 2020, OrgCode, the tool's developer, announced it would move away from the VI‑SPDAT and encouraged communities to adopt alternatives.

Some CoCs are now replacing it with machine‑learning systems, but little research shows that such systems allocate more fairly. This study tests whether language models, a readily available AI alternative, are more accurate or less biased than the tool they might replace.

Research question

Given the same client records, how do AI‑based models compare with the VI‑SPDAT in accuracy and demographic bias?
Hypothesis (stated before data collection)

The AI‑based model will outperform the VI‑SPDAT in accuracy but remain slightly skewed against people of color.

Result

Not supported on either count. Every AI run was less accurate than the VI‑SPDAT (mean absolute error 2.32–3.66 points against 0.97), and no run showed a significant race effect. The AI runs did catch nearly every truly high‑need person the VI‑SPDAT missed through underdisclosure, at the cost of flagging many who were not.

Data source

Real VI‑SPDAT assessments are protected by privacy law, but OrgCode published the interview and scoring method, which remains available through CoCs that adopted it. The study applies that method to its own synthetic population.

Contribution and limitations

The study offers a controlled audit of AI‑based vulnerability scoring against the instrument it could replace: the same records, varied one demographic attribute at a time, with every contrast paired within profile.

Limitations

  • Ground truth favors the VI‑SPDAT. True vulnerability is the VI‑SPDAT total under full disclosure, so the VI‑SPDAT is exact on half the records by construction. The AI tools never saw the scale's anchors, so their mean offset partly reflects calibration rather than judgment; rank correlation is the fairer comparison.
  • Synthetic population. Thirty‑two profiles vary less than real caseloads. The set spans every total from 0 to 17 and oversamples both decision thresholds, but findings may not transfer to real assessments.
  • Limited power for small race effects. Each race contrast pairs 128 instances, enough for 80% power at dz ≈ 0.25 uncorrected or 0.33 under Holm correction, roughly 0.3–0.5 points. Smaller race effects cannot be ruled out.
  • Models, not deployed systems. The machine‑learning tools CoCs adopt are proprietary; general‑purpose language models stand in for them, and results may not transfer.
  • One model per developer, one run per session. Each tool runs at its default settings (ChatGPT as gpt‑6‑luna through Codex; Claude as claude‑sonnet‑5 through Claude Code), which may differ from the consumer chat apps. Run‑to‑run variation is not measured. The two ChatGPT runs show that a single setting (reasoning effort) can change both accuracy and the gender result.
  • Awareness of the manipulation. A model that recognizes the demographic contrast may equalize scores by design rather than by fairness. Detailed narratives reduce but cannot eliminate this risk.
  • Location is stated, not lived. Narratives read plausibly in all five cities, so the study measures response to the city label, not to local conditions such as rent or climate. Race × city interactions are not estimable.
  • Gemini is not yet included. Its run is incomplete because of the free API tier's daily request limit.
